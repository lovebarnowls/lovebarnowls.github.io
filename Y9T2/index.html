Case File — Faithful Web Investigators

Behind the Web

Year 9 Term 2 · Digital Technologies

The brief

You have just started as a junior cybersecurity web development engineer. Each week, your firm is handed a new client site to investigate — a small, real-looking business that has asked for a security review before it goes live.

Your job is to find what a careless developer left behind: comments that should never have shipped, pages nobody linked but everybody can reach, data hiding in plain sight. Every flag you find and submit proves you found something real.

Your own site, for the formative assessment

Alongside the weekly labs, you will use AI to help you build a small site of your own that plants a set of flags for a classmate to find — the same idea as the labs, but you are the one deciding what to hide and where. This is not the same as building a genuinely, intentionally vulnerable website: real security flaws are dangerous to leave lying around, even as an exercise, so your site only ever needs to look the part.

Later, you will swap sites with a classmate and write a short audit report on what you find in theirs — using the same skills the weekly labs are building.

A few things to know before you start

  • Every business, person, and story in these labs is fictional. Any resemblance to a real company or website is coincidental.
  • All images used across the labs are AI-generated, not real photographs.
  • Each lab is a self-contained sandbox. In real life, a web address with a # in it is not a separate page — that is a simplification made for this unit, not how the real web works.
